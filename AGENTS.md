## graphify

This project has a knowledge graph at graphify-out/ with god nodes, community structure, and cross-file relationships.

When the user types `/graphify`, invoke the `skill` tool with `skill: "graphify"` before doing anything else.

Rules:
- For codebase questions, first run `graphify query "<question>"` when graphify-out/graph.json exists. Use `graphify path "<A>" "<B>"` for relationships and `graphify explain "<concept>"` for focused concepts. These return a scoped subgraph, usually much smaller than GRAPH_REPORT.md or raw grep output.
- Dirty graphify-out/ files are expected after hooks or incremental updates; dirty graph files are not a reason to skip graphify. Only skip graphify if the task is about stale or incorrect graph output, or the user explicitly says not to use it.
- If graphify-out/wiki/index.md exists, use it for broad navigation instead of raw source browsing.
- Read graphify-out/GRAPH_REPORT.md only for broad architecture review or when query/path/explain do not surface enough context.
- After modifying code, run `graphify update .` to keep the graph current (AST-only, no API cost).

Agentmemory coordination:
- Use graphify for current codebase structure, call paths, and file relationships.
- Use agentmemory for cross-session decisions, unresolved questions, and prior work history.
- When saving graph-derived context to agentmemory, save a short decision or finding with concept tags; do not store full Graphify reports or large query outputs.
- Prefer scoped `graphify query "<question>" --budget 1200` before broad file reads, then use agentmemory recall only when the question depends on past sessions.

## Skill stack (Cursor handoff)

Installed skills and how they work together. Full precedence rules live in `.cursor/rules/skills-orchestration.mdc`.

| Skill family | Location | Role |
|--------------|----------|------|
| graphify | `.codex/skills/graphify/`, `.cursor/rules/graphify.mdc` | Codebase knowledge graph |
| agentmemory | `.agents/skills/agentmemory-*`, `recall`, `remember`, `handoff` | Cross-session memory (MCP at `~/.cursor/mcp.json`) |
| superpowers | `.agents/skills/brainstorming`, `writing-plans`, `test-driven-development`, etc. | Feature workflow and TDD |
| ui-ux-pro-max | `.cursor/skills/ui-ux-pro-max/` | Design system research (planning phase) |
| design-taste-frontend | `.agents/skills/design-taste-frontend/` | Frontend implementation and polish |
| ponytail | `.agents/skills/ponytail*` | Minimal code for backend/utilities (not UI design) |

Conflict resolution:
- **UI**: ui-ux-pro-max (research) → design-taste-frontend (build). Ponytail does not apply to frontend visual work.
- **Workspace UI** (`src/features/swinlearn/**`): ui-ux-pro-max primary; taste-skill excludes dashboards.
- **Tests**: superpowers TDD overrides ponytail minimal-test guidance.
- **Knowledge**: graphify first for structure; agentmemory for past-session context.

Design system: `design-system/swinlearn/MASTER.md` (generated by ui-ux-pro-max).

Health check: `powershell -File scripts/verify-skills.ps1`

Start agentmemory (Windows): Docker Desktop on → `scripts/start-agentmemory.cmd` (uses `docker compose --profile agentmemory`)

Stop agentmemory engine: `scripts/stop-agentmemory.cmd`

Update skills: `npx skills update -p` from project root.
